# 按项目定制远征队世界设定

日期：2026-10-18。状态：需求与实现约定；本文不代表插件接入和自动刷新已经完成验收。

需求来源：用户要求「其中远征队的背景设定能够通过不同的项目，由模型修改设定」，随后要求将这套逻辑写入仓库 Markdown。

## 产品行为

Terminal Colony 是默认世界。每个项目可以拥有自己的背景故事、队伍名称、角色称谓和设施名称，由模型结合项目内容生成，也可以由用户指定方向后修改。

例如，基础设施项目可以表现为「轨道维护站 / 维修舰队」，数据分析项目可以表现为「深海研究所 / 科考队」，游戏项目可以表现为「符文工坊 / 冒险团」。这些名称表达项目氛围；实际出现多少 Agent、执行什么工具、哪些调用失败，均由真实 trace 决定。

项目世界设定属于表现层。它可以跨同一项目的多个会话复用；执行事实、回放游标和当前选中对象仍按会话隔离。首次打开没有设定的项目时使用默认世界，不自动发起模型调用。

## 保存位置与作用域

在当前会话所属的项目根目录保存 `.agentarium/world.json`。项目根目录取自宿主确认的工作区，不跟随终端中的临时 `cd` 改变，也不使用其他项目或其他浏览器窗口的设定作为回退。

- 同一工作区的会话读取同一份项目设定。
- 不同工作区分别读取各自的文件；同一仓库的不同 worktree 按各自工作区处理。
- 文件可以纳入 Git，由项目团队共享，也可以按项目需要加入忽略规则。
- 读取通过 dsh 现有的会话授权文件接口完成，适用于宿主支持的本地或远程工作区。读取不可用时显示默认世界和原因。

优先级为：通过校验的当前项目文件 → 内置默认设定。首版不引入用户全局覆盖、跨项目自动继承或会话临时覆盖。

## 模型修改流程

1. 用户在对话中提出需求，例如「把这个项目的远征队设定为深海科考队，按仓库用途给设施命名」。插件可提供「复制设定提示词」入口，供用户发给当前会话。
2. 模型读取已有设定及完成这项请求所需的项目说明，遵循用户指定的风格，生成或修改 JSON。已有字段应尽量保留，只有受请求影响的内容需要改变。
3. 模型通过已有文件工具写入 `.agentarium/world.json`。创建文件、修改文件、审批与失败处理均沿用 dsh 的原有机制；不增设绕过文件权限的写入通道。
4. 插件在首次进入、切换会话或工作区、重连后读取设定。观察到可能修改文件的工具结算时，合并短时间内的触发并重新读取；同时提供「刷新设定」作为手动补充。无关 trace 更新不应逐条触发模型调用或文件读取。
5. 插件校验新文件，通过后一次性替换表现设定。刷新不会重启 Agent、改写执行记录或把真实执行移回某个历史时间点。

模型生成只在用户明确提出设定需求时发生。打开插件、执行工具或切换项目，本身不授权插件自动要求模型改写项目文件。用户也可以直接编辑 JSON，效果与模型修改相同。

## 文件格式

以下为示例，可保存到项目的 `.agentarium/world.json`：

```json
{
  "version": 1,
  "name": "深海研究所",
  "squadName": "科考队",
  "story": "队员在深海观测站协作，收集证据、验证发现，并把结果带回指挥舱。",
  "leaderTitle": "首席研究员",
  "specialistTitle": "科考员",
  "accent": "#a2c6d9",
  "facilities": {
    "hq": "指挥舱",
    "archive": "样本档案室",
    "workshop": "设备维修间",
    "terminal": "控制终端",
    "test": "实验舱",
    "web": "声呐观测站",
    "portal": "潜航通道",
    "utility": "综合工作站"
  }
}
```

| 字段 | 含义 | 约束与默认值 |
| --- | --- | --- |
| `version` | 配置格式版本 | 必填，首版固定为 `1` |
| `name` | 世界或基地名称 | 1–24 个字符，默认「智能体基地」 |
| `squadName` | 队伍名称 | 1–16 个字符，默认「远征队」 |
| `story` | 明确标识为背景设定的说明 | 1–240 个字符，默认「一个安静的智能体基地。观察执行，追溯事实。」 |
| `leaderTitle` | 主 Agent 的世界观称谓 | 1–24 个字符，默认「主控 Agent」 |
| `specialistTitle` | 子 Agent 的通用世界观称谓 | 1–16 个字符，默认「队员」 |
| `accent` | 装饰与选中态的主题强调色 | 六位十六进制颜色，默认 `#c7e99b` |
| `facilities` | 固定设施 ID 对应的显示名称 | 可省略或只覆盖部分；每个名称 1–16 个字符，其余保留默认名称 |

除 `version` 外的字段省略时使用默认值。文字去除首尾空白后应为非空，不接受控制字符和换行。文件上限为 16 KiB，读取被截断时不得尝试应用残缺 JSON。未知字段不产生额外能力，未来格式通过版本演进。

设施 ID 固定为 `hq`、`archive`、`workshop`、`terminal`、`test`、`web`、`portal`、`utility`。模型只能修改这些设施的显示名称，不能通过新增 ID 注册工具或改变工具分类。首版仍复用既有 ASCII 建筑和角色图形；自定义图片、脚本、任意 CSS 和外部资源地址不在配置范围内。

## 世界设定与执行事实的边界

| 可以修改的表现 | 必须保持的事实 |
| --- | --- |
| 「远征队」改为「科考队」 | 可见队员数量及真实 Agent 身份 |
| 主 Agent 称为「首席研究员」 | `A0`、原始名称或身份、父子关系、会话 ID |
| 「制造工坊」改为「设备维修间」 | 工具名称、分类、参数和结果来源、callId |
| 增加世界背景故事 | 用户任务、真实执行摘要、错误原因与审批状态 |
| 更换装饰强调色 | 失败、审批、取消、未知等状态的文字与可辨识度 |

检查器保留实际 Agent 身份与任务标签，主题称谓作为展示层信息。世界故事需要标为「背景设定」，不能混入执行事件列表或冒充模型的真实思考。

配置不接受工具执行、自动审批、改变权限、伪造 Agent、指定成功或失败、完成百分比等能力。文件中的文本仅按普通文本展示，不执行 HTML、JavaScript 或提示指令。失败和待审批等关键信息必须保持可见，主题颜色不得降低其可读性。

## 刷新、回放与错误处理

- 初次读取没有文件：使用默认世界，提示可通过模型定制；这不属于执行失败。
- 文件不合法、版本不支持或读取失败：显示具体的设定加载提示。当前项目已有有效设定时保留该版本；否则使用默认世界。不得出现一半旧字段、一半新字段的混合状态。
- 切换项目：立即清除上一项目的设定，再加载当前项目。加载完成前使用默认值；较早请求的迟到响应必须丢弃。
- 删除设定文件：刷新后恢复默认世界；撤销修改可通过编辑文件或 Git 完成。
- 回放：首版用当前有效设定呈现历史事实，并标注「使用当前世界设定」。不宣称还原当时的世界观，也不将实时审批状态投影到历史时点。历史设定快照留待后续版本。
- 退出视图或卸载插件：取消在途读取，清理订阅、定时器和主题样式；不修改项目文件。

## 验收清单

- [ ] 两个项目保存不同设定，切换后世界名称、队伍、角色称谓和设施名称各自正确，无串用或迟到响应覆盖。
- [ ] 同一项目的不同会话复用设定，执行事件与角色身份仍按会话隔离。
- [ ] 用户让模型修改文件后，自动刷新或手动刷新能够应用；读取失败时有明确提示。
- [ ] 仅有 `version: 1` 的文件使用其余默认值；部分设施覆盖不会抹掉其他默认设施。
- [ ] 非法 JSON、不支持的版本、超长或截断内容、错误字段类型和无效颜色均不会破坏主视图。
- [ ] 设定刷新前后，同一批 trace 的 callId、时间、事件顺序、Agent 关系、成功、失败、审批与未知状态一致。
- [ ] 自定义文字不会作为 HTML 或脚本执行；不请求第三方素材；深浅主题及状态标记仍可读。
- [ ] 回放提示当前设定的适用范围；切换设定不改变回放游标或 Agent 运行状态。
- [ ] 未发起定制请求时，进入视图和执行工具不会自动调用模型生成设定或改写文件。
